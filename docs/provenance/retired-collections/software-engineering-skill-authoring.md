# Skill Authoring

This document defines the collection-level structure expected for
software-engineering skills.

## Scope

Skills in this collection own software-engineering workflows: implementation
process, architecture workflow, local QA, test strategy, build/check evidence,
debugging workflow, code-review execution, CI/release workflow, developer
infrastructure, engineering productivity, skills repository architecture,
MCP/tool backends, agent evolution, skill-evolution mechanics, Swift, SwiftUI,
Apple frameworks, SwiftPM, Xcode, Simulator, Instruments, and Apple-platform
implementation guidance.

They do not own product decisions, design critique, go-to-market execution,
or store/listing operations.

## Expected Skill Shape

Use this section shape unless a skill has a clear reason to vary:

- Purpose
- When To Use
- When Not To Use
- Inputs To Inspect
- Workflow
- Reference Files To Consult
- Decision Rules
- Validation Rules
- Output Format
- Failure / Uncertainty Handling

## Conservation Standard

For development-process upstream material, preserve:

- setup assumptions and required local state
- good and bad workflow shapes
- failure modes and diagnosis paths
- validation commands and evidence expectations
- screenshots, logs, traces, test output, or other proof shapes
- safety boundaries for live accounts, external services, and destructive
  actions
- tool, MCP, CLI, agent, and automation setup or failure-handling boundaries
- skill-evolution evidence rules when the workflow changes agent behavior

Do not compress workflow material into a pure command glossary.
