# Docs Truth Update Checklist

Use this checklist to decide which docs should become current truth.

- Does this belong in `Docs/Architecture`, `Docs/Reference`,
  `Docs/Proposals`, `Docs/Decisions`, `.agent`, `AGENTS.md`, or README?
- Is this current truth, evidence, proposal, historical note, or execution
  plan?
- Should accepted architecture move to `Docs/Architecture` or
  `Docs/Decisions`?
- Should uncertain options stay in `Docs/Proposals`?
- Should `.agent` hold only execution control?
- Is shipped text, including `Docs/Reference`, free of raw upstream wording,
  local paths, run notes, and donor comparisons?
- Are internal analysis terms (donor, upstream, superset, parity, "exceeds
  upstream") rewritten as what the product does and supports?
- Should `AGENTS.md` route agents to this doc?
- Should a README index it?
- Should a case capture be added?
- Does the doc state phase / stage judgment?
- Does the doc distinguish accepted boundaries from deferred layers?
- Can a future Codex session use the docs without hidden conversation context?
