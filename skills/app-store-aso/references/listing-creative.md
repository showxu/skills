# Listing Creative

Use this reference when ASO recommendations involve screenshots, app previews,
icons, Custom Product Pages, Product Page Optimization, or in-app events.
Route actual asset creation or file validation to `app-store-screenshots`.

## Screenshots And App Previews

- Treat screenshots as conversion assets that reinforce the listing promise.
- First screenshots should carry the clearest user outcome and match the
  metadata position.
- Use one message per screenshot. Avoid unsupported superlatives, awards,
  legal/medical claims, and feature claims not visible in the app.
- App previews should show actual app experience and should be understandable
  when muted.
- Localize screenshots and app previews for markets where localized metadata is
  used.
- Screenshot caption OCR indexing claims are advisory unless current reliable
  evidence is supplied. They can inspire tests, but should not be stated as an
  Apple rule.

## App Icon

- Icon guidance in this skill is strategic: distinctiveness, category fit,
  recognizability at small size, and testable hypotheses.
- Do not produce icon assets here.
- Icon appearance and asset specs belong to Apple design/asset workflows, not
  ASO ranking claims.

## Product Page Optimization

Apple Product Page Optimization can test up to three alternate product-page
versions against the original. Use it for testable creative questions:

- icon variants
- screenshot order or messaging
- app preview presence or ordering
- localization-specific creative treatment

Keep PPO advice evidence-based:

- define one hypothesis per treatment where possible
- avoid changing too many variables at once
- measure conversion rate, not just impressions
- wait for Apple Analytics confidence or enough data before applying a winner
- remember that live PPO setup, applying winners, and icon binary requirements
  are outside this skill's default actions

## Custom Product Pages

Custom Product Pages can vary screenshots, promotional text, app previews, and
assigned keywords. Use them when the user has distinct search intents,
audiences, campaigns, features, or seasonal messages.

Rules:

- Match assigned keywords to the intent of that page.
- Keep keyword combinations unique across pages when possible.
- CPP metadata must be reviewed before it is visible.
- If the app has not been approved yet, CPP submission may need to be included
  with the first iOS app version.
- Live CPP creation, deletion, submission, keyword assignment, or publishing
  requires explicit confirmation and usually belongs to `app-store-connect`.

## In-App Events

In-App Events can appear on the product page and in search results. Use them
for timely events such as competitions, premieres, live events, new seasons,
major updates, challenges, or special events.

Keep recommendations Apple-aligned:

- event name up to 30 characters
- short description up to 50 characters
- long description up to 120 characters
- event metadata should describe the event, not generic app promotion
- do not include unverified claims, all-caps shouting, excessive punctuation,
  or specific prices
- live creation, submission, and availability changes are not done here
