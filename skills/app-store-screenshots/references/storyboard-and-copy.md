# Storyboard And Copy

## Principle

App Store screenshots are listing assets, not UI documentation. A strong set
sells the product outcome through the app's real interface and a small amount
of clear supporting copy.

## Inputs To Gather

- App category and one-sentence value proposition.
- Top features in priority order.
- Raw device captures and app icon.
- Brand colors, typeface, and visual tone.
- Target device families and slide count.
- Locale list and any market-specific constraints.

## Narrative Arc

Use this as a starting shape, then adapt to the app:

| Slot | Purpose |
| --- | --- |
| 1 | Main benefit or strongest user outcome. |
| 2 | Differentiator or primary reason to choose this app. |
| 3 | Key workflow or proof of ease. |
| 4+ | One core feature per slide, in priority order. |
| Near end | Trust, craft, ecosystem, or compatibility note when relevant. |
| Last | Optional breadth slide for secondary features. |

## Copy Rules

- One idea per slide.
- Prefer concrete outcomes over feature inventories.
- Keep headlines short enough to read at thumbnail size.
- Control line breaks intentionally; do not rely on automatic wrapping.
- Avoid unsupported superlatives, awards, rankings, medical/legal claims, and
  vague promises.
- If a headline needs "and", it probably contains two slides.

## Compact Examples

| Weak | Better | Why |
| --- | --- | --- |
| Track habits and stay motivated | Keep your streak alive | One outcome, faster to parse. |
| Organize tasks with AI summaries | Turn notes into next steps | Outcome-first, less jargon. |
| Save recipes with tags and favorites | Find dinner fast | User benefit over UI feature list. |
| Manage budgets and never miss payments | See where money goes | Cleaner claim and less risk. |

## Layout Review

- First slide must be the clearest and strongest.
- Adjacent slides should not reuse the same composition.
- UI should remain inspectable; decorative elements must not block the app.
- Device frames should support the story, not become the story.
- Long sets should include rhythm: one contrast slide, one close crop, or one
  different device placement when appropriate.
- Do not imply a platform, device, award, ranking, certification, or capability
  the app does not have.

## QA Questions

- Can the first slide be understood in one second?
- Does each slide sell exactly one idea?
- Is the headline true when read without context?
- Does the screenshot visibly prove or support the claim?
- Are the first three slides the highest-value messages?
- Does every localized slide still fit and remain readable?
